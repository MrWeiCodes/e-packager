# 2026-10-12 剩余 98 个 Win32 回包失败的后续修复

## 范围与根因

基线为 `editable-repack-final-results.csv` 中 Win32 的 98 个回包失败：依赖模块 69、类型身份 21、窗口 6、声明 2。原样回包通过不等于语义重建正确；本轮继续使用底部已追加注释的工作区，所有产物位于 `D:\test`，原始工程不改动。

上一轮把 `dependency_module_not_found` 全部归为环境缺失的判断过于宽泛。直接原因包括：源码变化后清空了**原生声明身份与模块导入表**，导致已经嵌入工程的模块接口、类型 ID 和参数信息丢失。丢弃可执行快照不能连带丢弃这些非执行元数据。

## 实现

- **声明与执行分离**：修改后的本地方法强制重新语义编码；声明保留经过匹配的原生 ID。整方法复用和逐语句旧字节复用由独立开关禁止，不通过删除类型信息来间接阻止。
- **稳定映射**：页面按稳定 key 匹配原始声明，不按当前页面位置；参数、局部变量、程序集变量按名称匹配，只有类型文字未改变时保留未知原生类型。修改为不存在的新类型仍失败。返回类型加入声明元数据及目录序列化。
- **完整模块接口**：保留原始导入类、结构、成员和方法签名。缺少外部 `.ec` 时仍可用已存在的接口生成可编辑工程；没有原始接口的新依赖继续报错，不生成空模块。路径查找统一使用已有的 UTF-8 路径工具。
- **ID 分配冲突**：模块接口中的已知原生编号先预留，匿名声明不能先占用这些编号。此前导致已知成员被重新显示为匿名成员，真实 IDE 编译也因此失败。
- **必需基类**：文本导出与身份快照使用同一筛选规则；同一基类在导入接口和源码页中只生成一份，不再丢失注释或额外产生同名 `_2` 页面。
- **非执行名称元数据**：保留可丢失段中的外部符号 ID／名称及编辑器状态。新增编号从原始已分配上限之后分配，避免占用尚有引用的旧编号。
- **窗口属性**：事件绑定、事件定义和子控件不再送进专属属性更新回调。仅有基础属性和原始扩展数据时直接保留数据，不无故实例化第三方控件；真正修改专属属性仍需支持库接口。
- **事件类型**：支持库内部类型编号本来从 1 开始；已有高字的核心库／系统类型不能重定位到当前支持库。修正额外加一及错误换库问题。缺库时可保留 XML 显式索引与有效处理器绑定，并报告元数据不可用。
- **空 DLL 名称**：两例实际是 DLL 命令名为空，并非参数名为空。可编辑级别保留原始声明，严格语义验证仍报告缺名。原始 IDE 真实页面不显示该无名命令；不把它误称为可见源码丢失。

- **运行期与设计期属性**：SDK 将 `UW_ONLY_READ` 和 `UW_CANNOT_INIT` 定义为设计时不可用。窗口 XML 不再导出这些计算值，避免浏览器的“程序全路径”等值随工作进程变化而阻止跨架构回包。回包仍拒绝对只读属性的实际赋值；旧目录若含运行期属性，应从原 `.e` 重新拆包并合并已有源码修改后迁移，不能声称所有旧目录已经兼容。
- **未解析语句的文本传输格式**：写入 IDE 原始语句前还原目录文本中的转义标记；流程条件与普通语句统一导出，屏蔽代码保持原文。修复回包成功却把 `#e2txt_text#` 和反斜杠重复写进字符串的问题，连续两次修改后回包验证路径、换行、引号和字面量前缀。
